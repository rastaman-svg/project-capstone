POSTGRESQL — HOW TO RESET A PASSWORD (Windows)
================================================

There are two different situations. Check which one you're in before
following steps.


CASE 1: Reset the app's database user (ojt_app)
------------------------------------------------
Use this when you still remember the "postgres" superuser password and
just want to change ojt_app's password.

1. Open a terminal and log in as the superuser:

     psql -U postgres

2. Inside psql, run:

     ALTER USER ojt_app WITH PASSWORD 'your_new_password';
     \q

3. Update your .env file to match:

     DATABASE_URL="postgresql://ojt_app:your_new_password@localhost:5432/ojt_attendance"

4. Restart your dev server (npm run dev) so it picks up the new .env.


CASE 2: You forgot the "postgres" superuser password itself
-------------------------------------------------------------
This needs a temporary trick since you can't log in normally to change it.

1. Find pg_hba.conf. It's usually at:

     C:\Program Files\PostgreSQL\<version>\data\pg_hba.conf

2. Open it in a text editor AS ADMINISTRATOR. Find these lines near
   the bottom (yours may say "md5" instead of "scram-sha-256"):

     host    all             all             127.0.0.1/32            scram-sha-256
     host    all             all             ::1/128                 scram-sha-256

   Temporarily change them to "trust":

     host    all             all             127.0.0.1/32            trust
     host    all             all             ::1/128                 trust

   Save the file.

3. Restart PostgreSQL so the config reloads:
   - Press Win+R, type "services.msc", press Enter
   - Find "postgresql-x64-<version>" in the list
   - Right-click it -> Restart

4. Log in with no password (trust mode allows this) and reset it:

     psql -U postgres

     ALTER USER postgres WITH PASSWORD 'your_new_password';
     \q

5. UNDO THE pg_hba.conf CHANGE — change "trust" back to
   "scram-sha-256" (or "md5", whatever it originally said), save,
   and restart the PostgreSQL service again (same as step 3).

   Do not skip this step. Leaving it on "trust" means anyone with
   access to the machine can connect as any Postgres user with no
   password at all.

6. Verify it worked:

     psql -U postgres

   It should now prompt you for the new password you just set.


WHICH CASE AM I IN?
-------------------
- If you can still run "psql -U postgres" and it accepts your old
  password -> you're in Case 1, you only need to reset ojt_app.
- If "psql -U postgres" rejects every password you try and you have
  no other way in -> you're in Case 2.
